SDR Pipeline Architectures: Why Combine Elixir and Zig?

Welcome to your first lesson! Whether you are tracking amateur satellites, decoding APRS weather packets on 2 meters (144.390 MHz), logging FT8 contacts on 20 meters, or tracking 1090 MHz aircraft beacons, every Software Defined Radio (SDR) receiver solves the same physical problem:

How do you transform a blazing stream of digitized electromagnetic waves (megabytes of raw I/Q numbers every second) into verified, structured digital packets without dropping samples or melting the CPU?

In this repo, the codebase pairs Zig (via Zigler NIFs) with Elixir. Let's dissect the profound strengths and dangerous traps of this architecture for radio enthusiasts.

The Anatomy of a Radio Reception Pipeline

An SDR receiver can be cleanly divided into three distinct processing tiers:

  1. Micro-DSP (Heavy Math): Unsigned 8-bit or 16-bit In-Phase/Quadrature (I/Q) baseband samples arrive at millions of samples per second (2.0 MSPS in RTL-SDR = 4 MB/s continuous stream). Here, we calculate vector magnitude ($\sqrt{I^2 + Q^2}$), run matched filters, correlate preambles, and slice bits.
  2. Frame Dissection (Grammar): Once bits are identified, they form packet frames. We compute cyclic redundancy checks (CRC-24 / CRC-16), unpack callsigns, extract coordinates, and correct bit errors.
  3. Macro-State & Distribution (Orchestration): Managing active stations, evicting stale signals, publishing to networks (APRS-IS, local mesh, or web UI), and handling I/O backpressure.

The Upsides of the Elixir + Zig Architecture

1. Zero-Copy Binary Architecture

In Erlang/Elixir, binaries larger than 64 bytes are allocated on a global ref-counted heap. When Elixir passes a 64 KB chunk of radio I/Q bytes into a Zig NIF, zero memory copying occurs. Zig receives a direct pointer to the BEAM's memory buffer, applies SIMD vector math, and returns without memory allocations.

2. Natural Backpressure via GenStage

In traditional C or Python radio scripts (like bare rtl_fm pipes), if the decoder falls behind, OS buffers fill up, samples silently drop, and packet phase locks fail. In Elixir, GenStage uses demand-driven flow control: downstream consumers ask for batches only when they are ready. If the CPU experiences load, the pipeline sheds load gracefully rather than blowing up memory.

3. Bitstring Pattern Matching for Protocols

In C, decoding an amateur radio packet (such as AX.25 or Mode-S) requires tedious bit-shifting and bit-masking logic that is notoriously prone to off-by-one bugs. Elixir's binary syntax lets you extract fields declaratively: 

<<df::5, ca::3, icao::24, payload::binary-size(7), parity::24>> = frame
4. Cluster-Ready Radio Networks

HAM radio excels at distributed receivers: two antennas 10 miles apart can hear what one misses. Because Elixir runs on the BEAM, broadcasting decoded packets across a distributed mesh or cluster of Raspberry Pis requires almost zero extra networking infrastructure—using built-in :pg (process groups) or Phoenix.PubSub.

The Shortcomings & Traps

Trap 1: The 1-Millisecond NIF Rule

The Erlang VM relies on cooperative, preemptive scheduling. Erlang schedulers expect functions to yield every millisecond. If a Zig NIF runs longer than 1 millisecond without yielding (e.g., trying to process a huge 10 MB audio buffer in one tight loop), it blocks the scheduler thread, stalls heartbeat timers, and causes cluster network timeouts!

The Fix: Chunk data into bounded slices (such as 64 KB chunks, which take ~32 ms of real radio time at 2 MSPS, but execute in Zig SIMD in under 0.15 ms), or mark long tasks as dirty schedulers.

Trap 2: Context Switch Overhead

Calling across the NIF boundary has a small invocation cost. If you call Zig on every 10 samples, context-switch overhead will devour your CPU. The chunk size must balance latency against boundary overhead.

Trap 3: Not Suited for Hard Real-Time TX Modulation

This architecture is brilliant for receivers (RX) and packet decoders. However, for strict half-duplex transmit (TX) switching—such as hitting precise 30 ms TDMA time-slots in digital mobile radio (DMR)—BEAM garbage collection pauses and OS scheduling jitter make pure microcontroller firmware (C/Zig on bare metal) a better choice.

Checking Your Intuition

1. Why is a 64 KB chunk size safer for an SDR Zig NIF than a 10 MB chunk?
  • Zig cannot compile functions that process memory buffers exceeding one megabyte.
  • Executing long NIF loops stalls BEAM scheduler threads and harms soft realtime.
  • Elixir binary pattern matching crashes whenever binaries exceed sixty-four kilobytes.
  • Radio tuners like RTL-SDR will physically overheat when transferring large chunks.
Correct! Erlang schedulers need threads to yield within ~1 millisecond. Processing smaller 64 KB chunks keeps Zig execution times far under 0.2 ms, ensuring the BEAM schedulers remain responsive and healthy.
2. Where does this hybrid architecture deliver the highest operational benefit in HAM radio?
  • Synthesizing high-precision nanosecond RF carrier pulses for UHF transmitters.
  • Generating multi-gigahertz radar sweep waveforms on bare microcontroller chips.
  • Building distributed receiver networks that decode and deduplicate packet bursts.
  • Emulating physical analog inductors and quartz crystal filters inside software.
Correct! The combination of fast native DSP (Zig) and painless distributed messaging/supervision (BEAM) makes it unbeatable for multi-receiver digipeaters (like APRS or FT8 monitors) that pass packets across nodes.
